# 配色与默认状态归属审计

本记录对应 P05-BI。它描述当前源码、已验证的兼容约束和下一步提取边界，**不是已经实现的配色 Resource API**。BI 审计基线包为 Windows Debug `1.3.0.55`；BJ 后续修复构建为 `1.3.0.56`，实包颜色提交、保存、重选和重置已通过两轮本机补验。

## 实际数据流

默认入口 `project.godot` → `showcase/wardrobe.tscn` → `wardrobe.gd`。`wardrobe_state.gd` 同时承载银狼七组配色、展示状态初值和 schema 1–10 读取器。

| 环节 | 当前行为与责任 |
|---|---|
| `_ready()` | 校验完整角色定义；创建 `STATE.new(_active_character_id)`，捕获调试默认值，加载方案，再创建 UI。 |
| `_build_clothing()` | 直接读 `STATE.PALETTES` 生成标签、色块、按钮及初始选中状态。 |
| `_select_palette()` / `state.select_palette()` | 按索引替换三通道颜色；选择函数会 clamp，传 -1 不会进入自定义模式。 |
| `_color_changed()` | 修改一个颜色通道、强制 alpha=1，并设 `palette=-1`；其余 RGB 不变。 |
| `_apply_state()` | 把三颜色传给 Body 的 garment uniforms；**仅 `palette==0` 将 `u_npr_garment_mix` 设为 0**，其他合法值为 1。 |
| `save_scheme()` / `to_data()` | 写 schema 10、角色身份、palette 索引和三条六位 RGB；没有存储标签或预设表版本。 |
| `load_data()` | 先迁移、完整验证，再赋值；颜色以存档内容为准，不按 palette 重算。失败保持原状态。 |
| `reset_scheme()` | 重建整个状态，重置临时显示/动态，保留当前页和保存路径；不自动保存。 |
| `configure_save_path()` | 入树后重建默认状态，再加载指定文件；这是第三条工厂状态创建路径。 |

相关代码：[状态与迁移](../../showcase/wardrobe_state.gd)、[展示与保存](../../showcase/wardrobe.gd)、[配色按钮](../../showcase/wardrobe_palette.gd)。

## 必须保持的 schema 10 语义

1. **0 是原材质标记，不只是数组首项。** 即便文件里的 RGB 与原色预设不同，0 仍关闭染色。仅把表搬成 Resource 而让第 0 项变成任意染色预设，会改变既有像素。
2. **-1 是自定义标记。** 它由颜色编辑写入；选择预设的 clamp API 不负责选择自定义模式。
3. **保存的 RGB 是权威颜色快照。** 正数预设索引与颜色不一致仍是有效方案，加载不能自动套用当前预设 RGB。
4. 角色 ID 决定文件归属；同一身份的预设索引是持久语义。未增加显式迁移之前，不能重排/删除旧槽位，也不能通过 clamp、回退到原色或丢弃字段“修复”加载。
5. 读取、重置、重新绑定路径和重建必须使用同一套实例配置。源 Resource 的后续修改不得悄悄改变已打开实例的索引范围或重置结果。
6. 旧 schema 的填充值是历史迁移约定，不能机械替换成某次新作者配置的默认值。新角色的工厂默认值与旧方案迁移需分开处理。

## 归属分类与下一步边界

| 数据 | 判断 | 后续处理 |
|---|---|---|
| 七组名称及三通道 RGB | 样例展示美术配置，不是标准角色必须同色 | 单独提取作者配色输入，银狼保持原顺序/原值。 |
| 原材质/自定义标记、主色/辅色/饰边通道 | 当前染色与存档协议 | 暂不改 schema，明确保留 0/-1 语义。 |
| 初始配色、默认三色 | 和作者预设及保存协议耦合 | 与配色输入一起设计；不允许只改 UI 而遗漏重置和路径重载。 |
| 表情、眼嘴符号、动作枚举 | 已有运行时能力/状态协议 | 不作为银狼配色资源字段，不一并搬动。 |
| 湿润/风/特效关闭等中性开关 | 展示初始策略 | 本轮保留，不用通用字典覆盖任意状态字段。 |
| 袜口高度 1.34、范围 0.5–1.55；织物参数默认值 | 混有空间校准、展示调节范围及历史迁移值 | 另开有界校准审计，不能声称配色提取能关闭所有默认状态工作。 |

下一步拟实现独立的展示配色作者配置：基础渲染可省略、完整展示显式提供；固定原材质槽位 0，显式有序名称和三颜色输入，校验不为空/结构一致/合法 RGB。进入展示时复制快照，UI 和三条状态构造路径都消费同一份配置。具体类型/API 尚未落地；不增加任意模型适配，也不为此自动升级用户方案。

## 验证证据与边界

`palette_contract_regression.gd` 使用真实展示场景和真实按钮输入，固定已求值中性姿态，截图等待不推进模拟。它覆盖七组名称/RGB/真实 GPU 变化、0/-1 标记、保存颜色权威性、schema 1–9 自定义颜色迁移、非法输入原子拒绝、实例隔离、重置、路径重载、重建和磁盘字节往返。

`fixtures/silver_wolf_schema10_defaults.json` 是 .55 真实包隔离目录保存的原始默认方案，作为历史兼容基线，不是运行时 fallback。检查默认状态的正式保存字节与该文件完全相同，并通过正式读取器验证恢复后的运行时值；不把 JSON 解析后统一为 float 的字典直接当成有 int 字段的内存字典。

真实 GPU 负对照在“原材质 + 不同 RGB”状态下临时强制开启染色，要求同一张全画面 PNG 比较检出变化，再恢复并要求字节完全一致。负对照只改测试实例材质，不改生产 shader、不扩张区域或放宽阈值。此专项不替代衣装作者域检查或实时全序列验收。

颜色编辑后的按钮选中状态单独记在 `observations.custom_color_selected_buttons`，不是“必须保留”的兼容断言。状态正确不代表 UI 选中标记已经同步；若仍选中旧预设，应单独修复，不把历史缺陷钉成正确合同。颜色对话框本身的完整桌面交互不在本专项覆盖内。
