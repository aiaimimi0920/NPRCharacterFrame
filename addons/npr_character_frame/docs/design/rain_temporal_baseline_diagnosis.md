# P05-BT 静态画面漂移诊断

## 当前结论

雨水 CPU、heads 和 trails 不变，并且不执行测试纹理上传时，正常丝袜视角仍可在两张相差少量一级像素的画面之间切换。进一步关闭 Body 的 `u_npr_rain_enabled`，也复现相同量级漂移。因此水滴模拟、移除单颗粒子和上传快照都不是该现象的必要条件；不能据此修改雨水生产算法。

**根因尚未定位，严格时序视觉验收仍未通过。** 没有提高差分阈值、裁掉差异区域或关闭阴影来替代正常渲染验收。试验中“未复现”只覆盖本次输入与采样窗口，不是排除间歇性问题的充分证据。

## 真实入口与测量边界

入口为 [wardrobe.tscn](../../showcase/wardrobe.tscn)，银狼角色配置保持；只冻结姿态来隔离视觉变量。雨水生产数据由 [npr_surface_rain.gd](../../runtime/rain/npr_surface_rain.gd) 管理，GPU 场见 [npr_rain_field.gd](../../runtime/rain/npr_rain_field.gd)。所有暂停、改材质开关和替换诊断 shader 只在一次性测试实例内执行，不写回角色配置或保存方案。

原始图像采用 SHA-256 命名去重，逐帧 JSON 记录图像身份；分析器重新解码原 PNG 并核对 RGBA 哈希，逐字节比较，不经过有损视频或阈值筛选。GDScript 中的 CPU/纹理/生命周期检查与 Python 图像门禁分开报告；前者 `REGRESSION_OK` 不代表后者通过。

本机引擎为 `4.8.dev.custom_build.38b6ddee7`，当前匹配源码位于开发机引擎根的 `engine/` 子目录，HEAD 与发布 manifest 一致。该版本 `RenderingServer.frame_post_draw` 的本地 API 说明为所有 viewport 更新结束后发出，测试已在该信号后读图。Context7 查询失败，未把远程查询结果冒充已确认文档。未修改引擎。

## 两个被纠正的诊断前提

1. 当前拟合丝袜层在该默认测试配置中本来就不可见；仅执行 hide 不能证明它与漂移无关，也不能算一次有画面响应的 A/B。
2. [NPRKeyLightPool](../../runtime/npr_key_light_pool.gd) 将真实共享主光置于独立 `NPRWorldKeyHost`，不在展示 viewport 的子树下。只遍历 `_scene.viewport` 会漏掉真正主光。后续实验通过 `preview.character` 的 shadow rig 操作，记录真实灯光路径、`shadow_enabled`、可见性、MSAA、TAA 和 debanding 状态，并验证开关生效。

现有 [Body shader](../../shaders/body/body_npr.gdshader) 的诊断 7 在 `light()` 记录当前方向光 `ATTENUATION`，在 `post_light()` 输出；测试复制其代码并只替换这一条输出，保存完整诊断副本。生产 shader 及引擎均未编辑。

### 原逐点失败现场接入

`rolenpr2_p05_bt_failure_hook_20261001/hook_probe.gd` 继承原可见粒子观察器，先完整执行 `_head_pair()` 的恢复和 no-op 严格断言，再仅对第一次 temporal 图像失败采集现场输入和运行 sampler 对照。最终版本成功探针不增加 PNG 读回；原失败列表、stderr 和 EXIT1 都保留，不用诊断检查通过掩盖原失败。事件 on/off 图没有输入快照，不能用恢复时刻的输入替代。

三轮接入检查分别 1156/1156、1207/1207、1389/1389，独立 PNG 配对 96/96、114/114、122/122，均未触发现场分支。最后完全未修改的原 no-op 对照 1407/1407、124/124 配对通过，temporal 两组各 60。未复现不只出现在 hook 版本，但不能认定 hook 没有时序影响，更不能关闭历史间歇性失败。

本轮仅完成接入和成功路径验证，失败现场分支仍 NOT TESTED。当前缺少新鲜失败现场，停止追加同类独立搜索；保留低介入观察器在原专项下一次实际失败时采集。没有生产修复，不制造故障冒充重现，不降低严格 RGBA 门禁。

### 同 actor sampler 等价性校准

后续 `rolenpr2_p05_bt_sampler_20261001` 新增原 ViewportTexture 与等字节 ImageTexture 的 copy/original/copy/original 观察器。前两次各 1440 帧没有触发，未执行切换。第三次 1440 帧搜索也未触发，只在显式校准模式下执行四段各 360 帧的切换，34 条状态/类型/字节检查通过，所有图像稳定；返回原来源时暴露输入和图像恢复。

结果必须保留 `triggered=false`、`comparisons_ready=true`、`original_return_brackets_reproduced=false`。这只证明正常态 sampler 切换等价，不说明漂移修复，也不能依据静态稳定引入每帧纹理复制的生产开销。三次合计 5760 帧无新漂移，历史失败仍有效。

后续优先在原逐点 A/B/no-op 的真实失败入口挂接此观察器，而不是追加独立静态搜索。只有实际触发并保留同场景前后复现对照，才讨论来源相关性；其他 GPU 内部输入和非原子读回边界仍不变。

### 输入观测续接

后续证据 `rolenpr2_p05_bt_inputs_20261001` 已在 `candidates_r2` 抓到新的静态漂移：887 帧中的 15 帧，三组分别 73/65/73 像素、最大通道差 1；36 个实际输入观测点中，组内暴露的节点、骨骼、材质、实例参数与雨水/辅助纹理哈希未变化。原图、转换点和输入快照关联保存，不把未采集输入的帧当成实测。正常材质输出仍漂移，具体机制尚未证明。

快照不是完整 GPU 抓帧：有效 global overrides、引擎阴影 atlas、隐式附件和 shader TIME 未覆盖。当前引擎实际禁止游戏模式 global getters，相关试验保留 8 次 ERROR；观察器只记录明确标注的作者 globals。纹理 getter 新建 Image 包装对象按完整内容比较，分析器自测保留真实内容/标量变化及相同输入不同图片的检测。

补充版本 `candidates_r3` 保存 CPU 水状态、雨水 stamp/decay 输入、viewport 纹理原字节及尺寸/格式；960 帧未复现，不得把它当作 `candidates_r2` 坏帧的原始纹理或修复证据。先前逐帧快照 180 帧、低观测开销 1200 帧也只代表未复现。后续优先获得包含原纹理字节的同一坏帧，再比较普通材质/光影合成阶段；不通过额外开关组合“碰到绿色”宣称修复。

后续先为可复现的坏帧保存完整渲染输入快照，并在同一快照上比较材质数值、灯光/几何状态和 `npr_shadow_delta` / `post_light` 颜色合成路径；避免用不同自然雨水快照的“这次通过”代替因果验证。当前源码只读观察到 PCF 使用 `taa_frame_count`，测试 TAA 关闭；不凭这一点认定采样随机化或引擎 bug。只有确定实际机制后才做最小修改；引擎 patch 仍由用户负责。
