# 展示默认状态与袜口高度校准审计

对应 P05-BL 的历史审计。P05-BN 已实现 [展示高度校准](../model_authoring/showcase_height.md)：完整展示显式提供范围、工厂值与步长，三条状态创建路径和消费者共享入树快照。下文保留 BL 时的硬编码观察和提取边界；它们不再代表 BN 当前实现。BK 的作者配色配置已完成，本审计不重复配色工作，也不创建可任意覆盖状态字段的通用字典。

## 实际数据流与坐标

入口仍为 `project.godot` → `showcase/wardrobe.tscn` → `wardrobe.gd`。`wardrobe_state.gd` 的工厂袜口高度为 `1.34`；初始化、重置和入树后重新绑定保存路径都会创建状态。UI 的“袜口高度（米）”滑块使用 `[0.5, 1.55]`、步长 `0.01`，回调在相同范围 clamp；存档读取器严格验证范围，失败不修改原状态。

袜口高度的空间是 **展示 actor 静止空间 Y**，不是源模型局部坐标、当前动作后的世界 Y，也不是腿长百分比。具体链路：

1. `wardrobe.gd::_install_garment_regions()` 传入 `preview.global_transform.affine_inverse() * source.global_transform`。
2. `NPRHosieryProfile.build_regions()` 将源顶点转为 actor 静止位置；`CUSTOM0.r` 保存候选域，`CUSTOM0.yzw` 保存静止位置。
3. Body shader 用 `CUSTOM0.yzw.y` 与 `u_npr_hosiery_height` 比较；拟合薄纱共享 Body 网格和相同高度覆盖函数。
4. `wardrobe_visual_layers.apply_state()` 把同一状态高度传给拟合材质及 `surface_rain.configure()`，即使层隐藏或雨水未启用也同步。
5. 雨水 `_kind()` 对种类 5 的三角形按重心坐标插值烘焙静止 Y；`height >= selected_height` 或不透明度小于 `0.01` 时按皮肤处理。

银狼实测雨水与 Body 均为 21,273 顶点，逐顶点静止 Y 最大绝对差为 **0**。这是样例的实际输入一致性证明，不是新角色数据必然正确的保证。Body/拟合层边缘有单侧像素抗锯齿，CPU 雨水是分类阈值，不要求 CPU 类别与 GPU 边缘混合权重逐像素相等。

## 归属判定

| 数据 | 当前归属与结论 | 下一步边界 |
|---|---|---|
| 高度 `1.34`、UI/选择范围 `[0.5,1.55]`、步长 `0.01` | 含角色空间校准，仍硬编码于展示；不因几何 profile 改变而自动改变 | 需要独立、明确的展示高度校准输入，统一三条状态创建路径、滑块和选择函数 |
| `hosiery_profile.domain_height_range` | 已是作者定义的几何候选域，开区间，最终再与掩码和高度相交 | 不是滑块范围，不可直接拿几何域下界替换当前 UI 下界；修改需要重建几何 |
| schema 1–5 缺失高度时补 `1.34` | 历史迁移合同 | 不替换成新角色或新版本配置的工厂值 |
| schema 6–10 中已有高度 | 用户保存的权威值，当前严格验证后原样保留 | 不按新默认重算，不 clamp 修复坏文件；同一身份若缩窄允许范围，应保留旧范围或显式迁移 |
| 透明度 `0.5`、丝光 `0.20`、织纹 `0.035`、粗糙度 `0.27` | 无量纲的展示/lookdev 初值，不是空间坐标；后三项也有历史 schema 填充值 | 本切片不扩成“所有字段都角色化”；与几何高度拆开决定是否需要作者风格初值 |
| 丝光 `[0,0.5]`、织纹 `[0,0.1]`、粗糙度 `[0.18,0.6]` | 当前材质调节和存档协议范围 | 不因移动空间高度配置而机械改变；现有 `NPRStylePreset` 不承载这些状态 |
| 风、湿润、压力、降雨等初始关闭值 | 通用展示启动策略 | 继续保留，不加入任意状态覆盖器 |
| shader include 的高度默认/hint、雨水对象初始 `_height` | 非展示消费者也可读到的底层默认；完整展示会显式传入状态 | 本轮未改，不把它们误当成完整展示工厂配置或仅凭文本相同就一起替换 |

实测结构合法的替代 `hosiery_profile`（域 `[1.6,2.5]`）不会让状态读取器接受高度 `1.9`。这揭示展示校准尚未解耦；不是新模型几何贴合验收，也不把固定范围写成永远必须保留的通用设计。

## 后续高度提取的验收条件

- 明确有限递增的高度范围、正步长和位于范围内的工厂高度；使用可保留现有双精度存档端点的字段，不无意引入 `Vector2` 的 float32 端点收缩。
- 完整展示必须显式提供作者输入，基础渲染不强依赖展示 Resource；当前实例持有深复制快照。
- 初始、重置和保存路径重载使用同一配置；UI、setter、存档有效性检查和三个消费者一致。三消费者不得各自夹到另一套样例范围。
- 银狼原值、schema 10 默认文件字节和原画面完全保持。旧 schema 缺失高度的历史填充值仍为 `1.34`；如果某作者允许范围不含该历史值，应明确拒绝该旧方案而非改写数值，或先设计显式迁移。
- 限定范围与几何候选域、掩码和新角色尺寸的实际一致性需单独验证；不能只凭资源结构合法就承诺可见袜口位置正确。

## 另发现的镜头入口遗漏（BL 历史观察，BM 已修复）

BM 仅修复此入口的目标高度和水平偏移，现已消费实例作者镜头快照；质量评估距离 [3,7,18] 保留。镜头专项从 125/137 到 137/137；下述 BL 探针在 BM 重跑得到目标 Y 约 1.8、偏移约 0.1。袜口高度专项仍为 98/98、9 图不变；开放的高度校准未被此次修复关闭。以下保留问题发现时的事实。

`wardrobe_framework.gd::set_quality_view()` 仍硬编码目标 Y `1.55`，近/中/远距离 `[3,7,18]`，水平偏移 `0.34 * distance / 5.6`。BH 已提取的 `showcase_camera_profile` 没有覆盖此入口。

实际设置实例作者全身高度 `1.8`、全身距离 `6.0`、水平偏移 `0.2` 后调用近景质量视图：实际目标 Y 仍约 `1.55`，实际偏移约 `0.182143`；若沿用作者镜头既有按距离缩放规则，应为 `0.2 * 3 / 6 = 0.1`。保存状态未变化。此项作为 **待修复观察** 记录，不断言硬编码行为必须保留，也不声称 BH 覆盖了所有镜头入口。

下一有界修复优先让质量视图消费已存在的作者镜头快照；明确近/中/远距离属于质量评估协议还是作者校准，再处理高度初值提取。不要把两项未验证修改合并后一次性宣称全部默认校准完成。

## 证据

`hosiery_height_contract_regression.gd` 在真实展示中覆盖滑块信号、存档边界及原子拒绝、schema 1–10、Body/拟合/雨水三消费者、实际雨水三角形边界、GPU 高度变化及精确重置。开放校准和质量镜头限制放在 `observations`，不作为保留错误行为的成功合同。

专项本机证据与运行状态见 [实施记录](implementation_status.md)。当前程序检查不替代所有动作下的袜口质量、真实世界单位约束、第二角色、实时全序列或 Release 验收。
