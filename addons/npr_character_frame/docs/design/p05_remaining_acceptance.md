# P05 固定收尾清单

2026-10-02 按用户确认的收口方向冻结。本文是当前待办的唯一入口；[实施记录](implementation_status.md)及优化计划中旧切片的“下一步”仅为历史，不追加当前范围。P06、第二角色制作与外部 AI 实际评价不计入 P05。

## 完成定义与变更控制

现有约定功能在当前标准角色合同和提供的本机运行环境中可用；角色输入及模块责任明确；制作规范与检查规则一致；无未处置的已确认阻断性缺陷；主要使用流程、恢复、存档及有界稳定性完成验证；最后集成、包身份、使用说明一致，即完成 P05。

不要求所有模型、设备、极端尺度和参数排列均被穷举。新增必做项必须对应：已有功能实际错误、规范具体矛盾、已确认违反解耦目标的依赖，或下表内关键验收失败。必须记录原要求、证据、责任文件和关闭条件；不能仅以“未证明全部”扩张。新能力及额外优化另列建议，未经用户同意不进入本清单。

历史失败不改成通过。接受为已知限制须明确证据和影响，并由用户决定；“影响未定”不等于接受。

2026-10-02 前期用户要求尝试解决 BT 与实际语音；真实 WASAPI 输出和系统回环验证随后完成。原对话末尾用户改为“先忽略这个异常点”，现将 BT 登记为用户接受的已知限制，停止继续定位，不改写历史失败或宣称修复。当前进入交付收口，不重开已结算成果，不重复出包；物理听感尚无现场反馈，是否移交接收时人工复核仍待用户明确。见 [交付说明](../developer/release_handoff.md)。

- BY 累计 29 阶段集成，BZ Release `.63` 构建/启动及产物身份。

- 不再强制从 EXE UI 复刻 CF 人工遮挡夹具；保留其不是桌面 UI 证明的事实。没有实际缺陷，不新增角度搜索或测试专用产品入口。

### R1：仅核对这 8 项

本次结论及后续状态集中在 [固定收尾执行记录](p05_closeout_results.md)。

1. character definition、坐标/单位/canonical 骨序和资源引用。
2. 眼部、表情、符号目标及 blink/speech ownership。

4. 软组织、压迫数据及运行时责任。

6. 装备槽位、绑定与独立材质输入。

8. 湿润/雨水资源、模型输入与配置/检查规则。

核对代码、现有资源、制作文档及现行检查入口。canonical 合同、场景显式样例选择、同一展示层内部协作不重新提取；不新增模型、通用适配或作者参数。结果填写有限对照记录后关闭，不再次全库巡检。

### R3：固定运行计划与判据

- 使用当前正常场景，保留动作/眨眼/头发和真实雨水调度；预热 5 分钟，测量 30 分钟。按固定顺序执行降雨、暂停恢复、开关/重播及恢复；不增加随机矩阵。
- 日志无运行错误、无崩溃/挂起；暂停期间对应时钟/状态不推进，恢复后继续；已有雨水更新/粒子预算不超限。
- 内存增长比较相同配置下的前后稳定窗口：末 5 分钟中位数不高于首 5 分钟中位数 `max(64 MiB, 10%)`；对象/节点/孤儿/可观察渲染资源计数在同配置恢复点不得逐轮累积。超过即调查，不能事后放宽。
- 帧时间记录同配置窗口的 p50/p95/p99；末窗口 p95 不超过首窗口的 1.25 倍。该项是长时退化门禁，不宣称跨硬件 FPS 保证。截图采集/状态转换帧单独标记，不以采集耗时冒充产品耗时。
- 保存正常速度的有界连续画面或等效逐帧证据，检查水滴是否明显闪烁/跳变/持续停顿。静态严格差分仍按原门禁，归 R4，不更改阈值。
- 一次有效运行达标即停止；无效运行或发现具体失败保留证据，只修责任问题后重跑，不延长观察来碰到通过。

### R4：BT 有界处置

先审阅现有原图/报告，分别说明静态一级漂移和自然水滴连续性证据。最多补一次针对正常观看影响的固定采集，不重新开展随机 sampler/灯光/材质搜索。若证实产品可见缺陷则记录具体修复项；若建议接受为有限测量稳定性问题，必须提交用户决定。证据仍不足时明确“影响未定”，由用户决定是否接受阶段限制，不能擅自通过。

### R5：最终集成与交接

最后必要修改后跑当前 30 阶段 suite；重新核对生产输入与 EXE/PCK/DLL。生产不变复用 `.63`，有生产修改才按新编号出包并验证受影响流程。核对文档链接、UTF-8 无 BOM、检查入口及进程清理。R1–R4 全部完成或用户明确接受列名例外后，宣布 P05 完成并列出实际验证边界；P06 另行安排。
